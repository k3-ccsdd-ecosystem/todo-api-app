# 開発原則の既定

プロジェクトは 2-1 でこの既定を基に `02-design/principles.md` を確定する。確定後は本文書ではなく確定版に従う。

## 不変の原則

1. 要件定義書・設計書は常に人が読める形で保つ。AI 向けの形式（EARS、ID）は人が読む文書に付け足す
2. 要件は EARS で書き、要件 ID を設計・タスク・Issue・PR・テストへ継承する
3. 判定は人が行う。機械チェックは判定の前提であって代替ではない
4. 実装は Issue 単位で行い、PR は 1 Issue に対応する
5. テストは要件 ID に紐づける。未検証の要件を残したままリリースしない

## コーディング規約

- lint とフォーマッタの設定はリポジトリの設定ファイルに従う
- 公開 API と設定値は型と制約を明示する

## AI の振る舞い

- `delegation.md`、`security.md` に従う
- 分からないことは推測で埋めず質問する。質問は 1 回にまとめる
- 作業の結果は「何を作ったか」「何を確認したか」「未確認の点」に分けて報告する
