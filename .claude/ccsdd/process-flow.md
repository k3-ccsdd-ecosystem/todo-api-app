# 開発フローの工程一覧

CCSDD エコシステムが支える開発フローを、大項目 → 中項目 → 小項目に分けて定義する。ブレスト（[01-brainstorm.md](./01-brainstorm.md)）の「アイデア概要」から切り出したもので、成果物の形式・完了条件・担当（人 / AI）は、この表に列を足して管理する。成果物の置き場と実行対象の雛形は「雛形」列、先行事例（Fandhe-AI・Spec Kit・OpenSpec・AI-DLC・BMad Method）との対応は「先行事例」列に持つ。

この文書は `_tools/gen_process_flow.py` から生成する。編集はスクリプト内のデータに対して行い、再生成する（参照 ID の整合を機械的に保つため）。

- ID は「大項目-連番」。インプット欄は「ID + 成果物名」で、どの小項目のアウトプットを受け取るかを示す。エコシステムの外から来る入力は「（外部）」、既存システム由来は「（既存）」と書く
- 新規 / 既存の列は、その開発パターンで小項目が必要なら ○
- 「実現に必要な機能」は、その小項目を回すためにエコシステムが提供すべき機能。ここから必要な skill・agent・テンプレート・CI 部品を演繹する
- 「雛形」列は、その小項目を実施する機能（skill・CI 部品・成果物の置き場）を持つ雛形（spec = template-spec、app = template-app、infra = template-infra）。他のリポジトリの成果物が必要な場合は列ではなくインプット欄に書く（例: 6-12 の構築済み環境）。「app / infra」は同じ手順をそれぞれのリポジトリで実施する。判定記録・検証報告・進捗・監査は spec に集約する（bot・CI が書き込む）。spec リポジトリは新規・既存とも 1-1 で template-spec から作る（AI 設定・CI・品質ゲートを同梱）。A 群の部品（skills・CI 部品）は工程に対応させず、「実現に必要な機能」から紐づける
- 「先行事例」列は、その小項目に対応するプロセスを提供している先行事例の ID。後段で skill やプロセスの具体を設計するときの参考先。ID の採番規則と一覧は [prior-art-processes.md](./prior-art-processes.md)。空欄は対応するものが無い。任意で作成する成果物も対応に含める
- 2 章の基本設計書と、4・5 章の詳細設計書は、設計要素に ID を振り、参照する要件 ID を明記する。設計には要件の EARS に当たる記法レベルの標準が無いため、この 2 点とテンプレート準拠で AI が解釈しやすい形にする
- 文書を成果物とする小項目には共通で、AI のセルフレビュー（人が読める体裁、テンプレート準拠、抜け漏れ）を「実現に必要な機能」として含む。表では各行に繰り返さない
- 中項目が直前の行と同じ場合は空欄にしている
