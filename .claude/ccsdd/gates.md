# 完了条件

判定行では、gate-checker が機械チェックを行い、通った場合だけ人が判定を記録する。判定記録は該当章の `decisions.md`（spec）または `ccsdd/records/decisions.md`（app）に追記する。

## 判定記録の形式

```
## <工程 ID> <判定名>（<日付>）
- 結果: Go / No-Go / 保留（承認系は 承認 / 差戻し）
- 理由:
- 承認者:
```

## 機械チェックの項目

| 工程 | 判定 | チェック |
|---|---|---|
| 1-9 | 追求判定 | `brainstorm.md`・`plan-definition.md`・`research.md`・`scale.md` の必須節が埋まっている（プレースホルダ `<!-- TODO -->` が残っていない） |
| 1-13 | Go / No-Go | `poc-result.md` に検証項目ごとの判定がある。`poc-plan.md` の全項目に結果が対応する |
| 1-20 | 要件承認 | `requirements-ears.md` の全 REQ が 5 型のいずれかで、文が「なければならない」で終わる（例: しなければならない、返さなければならない）。明確化記録に未回答が無い。`constraints.md` が埋まっている。`00-ids.md` の REQ 一覧と本体が一致する |
| 2-16 | 設計承認 | `02-design/` の各文書の必須節が埋まっている。全 DES が 1 つ以上の REQ を参照する。`traceability.md` で全 REQ に DES が対応する。`principles.md` が確定している |
| 2-18 | 着手判定 | `tasks.md` の全 TASK が DES または REQ を参照し、推定工数と依存を持つ。全 REQ が 1 つ以上の TASK に対応する |
| 5-13 | マージ判定 | CI が成功。自己レビューの結果に未解決の指摘が無い。PR 本文に TASK-n と REQ-n がある |
| 5-23 | リリース判定 | カバレッジ報告で未検証の REQ が 0。乖離報告に未対応が無い |

## 逆戻り

判定が No-Go / 差戻しのときは、理由に戻り先の工程 ID を書く。戻り先の成果物を直してから再判定する。
